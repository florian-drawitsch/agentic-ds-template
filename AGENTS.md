# agentic-ds-template

Copier template for data science projects built with coding agents, and the plugin marketplace
those projects use, for Claude Code and Codex. Decisions are in `docs/adr/`: accepted ADRs
outrank code and tests, which outrank plans. The design overview is in
`docs/design/architecture.md`.

## Layout

- `copier.yml`, `template/`: the generated project (see the roadmap in the design overview). Only `template/` is rendered into projects.
- `catalog.toml`: single source for both marketplaces and local plugin manifests
- `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`,
  `plugins/*/.claude-plugin/plugin.json`: generated by `task build`; never edit by hand
- `plugins/*/`: plugins; `project` and `factory` ship scripts that generated projects copy by symlink
- `plugins/project/skills/<skill>/`: `SKILL.md`, `scripts/` (standalone, stdlib-only Python with
  inline script metadata), `assets/`
- `tests/`: pytest for scripts, the build and template rendering

## Commands

- `task setup`: install the locked development environment
- `task build`: regenerate marketplaces and manifests from the catalog
- `task check`: build check, ruff, ty, pytest and manifest validation; the merge gate
- `task security`: zizmor on the workflows and `uv audit` on the lock; CI adds a gitleaks scan
- `task dev`: register this working copy as a local marketplace in both CLIs
- `task eval`: score the `project` skills in `plugins/project/evals/` against a no-plugin
  baseline; spends model tokens, so it runs on demand, not in `task check`
- Run Python through `uv run`. If `VIRTUAL_ENV` points elsewhere, unset it first. Never use
  `--active`, which installs into the global interpreter.

## Rules

- Every plugin must work in Claude Code and Codex (ADR-0017). Skill text stays harness-neutral;
  harness-specific details go into scripts or clearly marked alternatives.
- Skills reference their own files as `<skill-dir>/...`.
- Scripts never trap an agent session: hook code paths catch every error and let the agent stop.
- A new skill ships only with tests for its scripts and evals that beat the no-skill baseline.
- Third-party bumps change `catalog.toml` only, after reading the upstream release notes.
- Conventional Commits, in responsibility-sized chunks. No agent attribution in commits or PRs.

## Tests

- `task test` stays under about 30 s. Each fast test gets 10 s for setup and 10 s for its call;
  `tests/conftest.py` fails tests over that. Longer tests are marked `slow` and run in
  `task test-e2e`.
- Render projects only through `tests/template/helpers.render`. It renders each set of answers
  once per process. Add assertions to a test that already renders the answers you need before
  adding a new answer combination.
- Extend an existing parametrize table or test before adding a new test function.
- Test logic with in-memory inputs and fakes. Use a real git repository only for git behaviour,
  and start it from `tests/helpers.checkout`.
- While working, run the affected file with `uv run pytest tests/<file> -q`. Run `task check`
  once before handing off.

## Writing style

Applies to everything you write here: replies, docs, docstrings, comments, commit messages.

- Answer first. Details as bullets, one idea each; numbered steps for procedures.
- No preamble, no restating the question, no process narration, no recap sections.
- No em dashes. Plain words over jargon; if a technical term is unavoidable, explain it briefly.
- One idea per sentence. Cut filler and redundant qualifiers.
- If unsure, say so and say how to find out.
- Precise, neutral, matter-of-fact tone.
