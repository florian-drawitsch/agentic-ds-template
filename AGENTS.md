# agent-kit

Curated plugin marketplace for Claude Code and Codex. It re-exports pinned third-party plugins
and ships the own `project` plugin. Design decisions are in `docs/adr/`.

## Layout

- `catalog.toml`: single source for both marketplaces and local plugin manifests
- `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`,
  `plugins/*/.claude-plugin/plugin.json`: generated by `task build`; never edit by hand
- `plugins/project/skills/<skill>/`: `SKILL.md`, `scripts/` (standalone, stdlib-only Python with
  inline script metadata), `assets/`
- `tests/`: pytest for scripts and the build

## Commands

- `task build`: regenerate marketplaces and manifests from the catalog
- `task check`: build check, ruff, ty, pytest and manifest validation; the merge gate
- `task dev`: register this working copy as a local marketplace in both CLIs
- Run Python through `uv run`. If `VIRTUAL_ENV` points elsewhere, unset it first; never use
  `--active`, which installs into the global interpreter.

## Rules

- Every plugin must work in Claude Code and Codex (ADR-0017). Skill text stays harness-neutral;
  harness-specific details go into scripts or clearly marked alternatives.
- Skills reference their own files as `<skill-dir>/...`.
- Scripts never trap an agent session: hook code paths catch every error and let the agent stop.
- A new skill ships only with tests for its scripts and evals that beat the no-skill baseline.
- Third-party bumps change `catalog.toml` only, after reading the upstream release notes.
- Conventional Commits, in responsibility-sized chunks. No agent attribution in commits.
